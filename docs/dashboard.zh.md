# 阅读 foldcrumbs 仪表盘

仪表盘是一个自包含的 HTML 页面，从你运行它的项目的存储即时生成：

```bash
cd 你的项目
foldcrumbs dashboard          # 在浏览器中打开
```

没有服务器，没有缓存：每个数字都在你运行命令的那一刻，由 CLI 使用的同一批
函数计算得出。凡是带链接的名字，都链接到磁盘上真实的记忆文件 — 如果某个
数字让你意外，点进去读源头。

本指南从上到下带你走一遍页面。

---

## 1. 主视觉区 — 这个存储活着吗？活得如何？

顶部横幅用一眼回答第一个问题。

**脉搏。**发光的圆圈在呼吸。它的节奏不是装饰：它来自存储真实的召回活动 —
沉睡的存储每 6 秒跳一次，每记录一次召回就加快一点，最快到 1.6 秒。如果
存储显得很忙碌，那是因为它*确实*忙碌。确切的节奏显示在 `pulse` 统计项中，
而它所依据的数字，就是旁边显示的 `recalls` 总数。

**统计项。**

| 统计 | 含义 |
|--|--|
| `memories` | 存储中的每一个文件，无论其状态 |
| `active` | 真正回应召回、出现在索引中的那些 |
| `recalls` | 记忆被拉入会话的总次数 |
| `federated roots` | 有多少个 agent 实例共享本项目的记忆视图 |
| `pulse` | 脉搏节奏，单位秒（见上） |

**健康徽章**（右上角）是由三个真实条件计算出的结论：

| 徽章 | 含义 | 该做什么 |
|--|--|--|
| `current` | 无衰减、无过期、无未决冲突 | 什么都不用做 — 存储整洁 |
| `needs a sweep` | decay 有候选项，或有已过期条目 | 运行 `foldcrumbs decay`（先 dry-run，再 `--apply`） |
| `attention` | 对账队列非空 | 运行 `foldcrumbs conflicts`，解决它列出的对 |

存储目录打印在统计项下方，所以你始终知道自己在看*谁的*记忆。

## 2. 面板逐一解读

主视觉下方的网格刻意做成不对称：通常需要阅读的面板获得更多空间。每个
面板都带一条彩色边和一个徽章 — **绿色**表示无事可做，**琥珀色**表示有
东西在等一次清扫，**红色**表示有东西在等*你*。

### Recall — reinforcement（召回强化）

哪些记忆一直在被需要，哪些从未被需要。

- 表格列出被召回最多的记忆及其次数 — 这些是项目的承重事实。
- 上方一行说明有多少记忆*从未*被召回。其中一部分是正常的（较新，或
  确实罕见）；在一个老存储上如果这个数字很大，说明有些记忆从未挣得
  自己的位置 — 看一眼之后，可以考虑 `decay` 或 `forget`。

### Federation — parallel roots（联邦并行根）

本机上为该项目注册的每一个 agent 实例。

- **绿点**标出你当前所在的实例；灰点是记忆以只读方式可见的其他实例。
- `entries` 是该实例当前发布的记忆数量；shard 时效表示发布的 freshness。
  shard 很旧意味着该实例已经一段时间没开会话了（没有东西坏掉 — 它最后
  发布的条目仍然可见，并被标记）。

### Trust（信任度）

活跃记忆的置信度分布（直方图），以及按记忆类型的平均值。

- 大部分质量应位于上方区间。低端肥大之处正是 `decay` 搜寻的地方。
- 按类型的平均值显示你对哪类记忆有把握（决策、规则），哪些是以推断
  方式进来、仍然存疑的。

### Decay（衰减）

清扫*此刻*会归档什么 — 与 `foldcrumbs decay`（dry-run）使用同一谓词。

- 名字旁的 `expired` 表示它是按日期过期的；数字表示它是按信任度衰减的
  （低于 0.3 且 30 天未被触碰）。
- 归档从不删除：文件留在磁盘上，`restore <file>` 可以恢复某一条，
  而 `prune --apply` 是真正删除文件的独立、显式操作。

### Anti-rot（抗腐化）

本机的上下文管理旋钮。

- `context budget` 与 `checkpoint at` — foldcrumbs 在何处做检查点，并
  建议你 `/compact` 或 `/clear`。
- `handoff age` — 实时工作状态快照的年龄；新鲜意味着存在一个可供
  `/clear` 后安全恢复的点。
- `semantic channel` — 可选的 embedding 召回是否开启，以及本地缓存了
  多少向量。

### Superseded（已被取代）

被取代、但为审计保留在磁盘上的记忆。每行是一条链：`旧 → 新`。当你确定
不再需要这段历史时，用 `foldcrumbs prune --apply` 清理。

### Expiry（过期，*当有条目带日期时出现*）

带 `expires_at` 的记忆。`lapsed` 统计已过日期（对召回已不可见）的条目；
`next to expire` 告诉你接下来到期的是什么。如果某个已过期记忆仍然成立，
就编辑文件：把日期往后移，或删掉那一行。

### Conflicts（冲突，*当队列非空时出现*）

对账队列的数字形式：LLM 无法裁决的含糊对、本存储对其他实例记忆提出的
主张、其他实例对本存储记忆提出的主张。面板指向 `foldcrumbs conflicts`，
那里逐条列出每个条目及解决它的确切命令。含糊会一直留在这里，直到你做出
决定 — 绝不会被猜测掉。

### Latest memories（最新记忆）

最新的活跃记忆，从新到旧 — 存储可供浏览的一面。每行链接到文件；日期与
类型在右侧。

## 3. 重新生成与选项

```bash
foldcrumbs dashboard                 # 生成并打开
foldcrumbs dashboard --no-open       # 只打印文件路径
foldcrumbs dashboard --out ~/d.html  # 写到你选择的路径
foldcrumbs dashboard --json          # 底层数据，而非页面
```

随时重新运行：页面永远反映存储*当下*的样子。
